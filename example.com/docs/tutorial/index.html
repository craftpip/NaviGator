Tutorial: Building a Real-Time Dashboard

In this tutorial, you'll build a live dashboard that displays server metrics using widgets.js. By the end, you'll have a working app with a line chart, a data table, and a status card — all updating in real time.

Time estimate: 30–45 minutes. You should be comfortable with JavaScript and have Node.js 18+ installed.

Prerequisites

  • Node.js 18+ — check with node --version
  • npm 9+ — check with npm --version
  • A text editor (VS Code recommended)
  • Basic familiarity with HTML, JS, and async/await

Environment setup

Create a new directory and initialize the project:

mkdir dashboard-example && cd dashboard-example
npm init -y
npm install widgets ws

The ws package provides WebSocket support for real-time updates.

1 Create the project structure

Create the following file structure:

dashboard-example/
├── index.html
├── server.js
├── src/
│   ├── data-source.js
│   ├── widgets.js
│   └── styles.css
├── package.json
└── README.md

The index.html file is the entry point:

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>Server Dashboard</title>
  <link rel="stylesheet" href="src/styles.css">
</head>
<body>
  <div id="chart"></div>
  <div id="table"></div>
  <div id="status"></div>

  <script src="node_modules/widgets/dist/widgets.min.js"></script>
  <script src="src/widgets.js"></script>
</body>
</html>
Tip: In production, you'd use a bundler (Vite, esbuild) instead of a direct script tag. This tutorial keeps it simple.

2 Build the data layer

Create src/data-source.js. This module fetches metrics from the server and normalizes them for the widgets:

// src/data-source.js
const WS_URL = `ws://${location.hostname}:8080`;

export class MetricsSource {
  constructor() {
    this.ws = null;
    this.listeners = new Map();
    this.buffer = [];
    this.MAX_BUFFER = 120; // 2 minutes at 1s intervals
  }

  connect() {
    return new Promise((resolve, reject) => {
      this.ws = new WebSocket(WS_URL);

      this.ws.onopen = () => {
        console.log('Connected to metrics server');
        resolve();
      };

      this.ws.onmessage = (event) => {
        const data = JSON.parse(event.data);
        this.buffer.push(data);
        if (this.buffer.length > this.MAX_BUFFER) {
          this.buffer.shift();
        }
        this.emit('data', data);
      };

      this.ws.onerror = (err) => {
        console.error('WebSocket error:', err);
        this.emit('error', err);
      };

      this.ws.onclose = () => {
        console.log('Disconnected. Reconnecting in 3s...');
        setTimeout(() => this.connect(), 3000);
        this.emit('disconnect');
      };
    });
  }

  on(event, handler) {
    if (!this.listeners.has(event)) {
      this.listeners.set(event, []);
    }
    this.listeners.get(event).push(handler);
    return () => {
      const arr = this.listeners.get(event);
      const idx = arr.indexOf(handler);
      if (idx > -1) arr.splice(idx, 1);
    };
  }

  emit(event, data) {
    (this.listeners.get(event) || []).forEach(h => h(data));
  }

  getHistory() {
    return [...this.buffer];
  }
}

Key concepts

WebSocket connection
A persistent bidirectional connection to the server. Unlike HTTP polling, data arrives in real time with zero latency.
Ring buffer
The buffer array stores the last 120 data points (2 minutes). Older points are shifted out to prevent memory growth.
Event emitter
A minimal pub/sub system. Widgets subscribe to events and auto-disconnect when destroyed.

3 Add the chart widget

Create src/widgets.js — the main entry point that initializes all widgets:

// src/widgets.js
import { createWidget } from 'widgets';
import { MetricsSource } from './data-source.js';

const source = new MetricsSource();

// --- Line chart: CPU usage over time ---
const cpuChart = createWidget('cpu-chart', {
  type: 'line',
  data: {
    labels: [],
    datasets: [{
      label: 'CPU %',
      values: [],
      color: '#0366d6',
      fillColor: 'rgba(3, 102, 214, 0.1)'
    }]
  },
  container: '#chart',
  theme: {
    primary: '#0366d6',
    gridColor: '#e1e4e8',
    fontFamily: 'system-ui, sans-serif'
  }
});

// Subscribe to live data
source.on('data', (point) => {
  const state = cpuChart.getState();
  const labels = [...(state.data.labels || []), point.time];
  const values = [...(state.data.datasets[0].values || []), point.cpu];

  // Keep last 60 points
  if (labels.length > 60) {
    labels.shift();
    values.shift();
  }

  cpuChart.update({
    data: { labels, datasets: [{ values }] }
  });
});

// --- Status card ---
const statusCard = createWidget('status-card', {
  type: 'card',
  data: { status: 'connecting', cpu: 0, memory: 0, uptime: 0 },
  container: '#status'
});

source.on('data', (point) => {
  statusCard.update({
    data: {
      status: 'live',
      cpu: point.cpu.toFixed(1) + '%',
      memory: (point.memory / 1024 / 1024).toFixed(0) + ' MB',
      uptime: formatUptime(point.uptime)
    }
  });
});

function formatUptime(seconds) {
  const d = Math.floor(seconds / 86400);
  const h = Math.floor((seconds % 86400) / 3600);
  const m = Math.floor((seconds % 3600) / 60);
  return d > 0 ? `${d}d ${h}h` : h > 0 ? `${h}h ${m}m` : `${m}m`;
}

// Connect
source.connect().then(() => {
  console.log('Dashboard live');
});
You should see: A line chart that updates every second, showing CPU usage over the last 60 seconds. A status card below it with current metrics.

4 Real-time updates with throttling

The chart above updates on every data point. For high-frequency data (100+ updates/sec), you need throttling. Here are three approaches:

ApproachProsConsBest for
Debounce (300ms) Simple, prevents rapid-fire updates May miss peaks User-driven updates (search, resize)
Throttle (1s) Consistent update rate Always waits, even under load Charts, live feeds
requestAnimationFrame Matches display refresh rate Complex batching logic needed High-FPS animations

For dashboards, throttling at 1 second (matching the data interval) is usually the right choice:

let pending = null;

function throttledUpdate(data) {
  if (pending) return; // skip if update already queued
  pending = requestAnimationFrame(() => {
    chart.update(data);
    pending = null;
  });
}

Add a data table widget for process-level metrics:

// Process table
const processTable = createWidget('process-table', {
  type: 'table',
  data: {
    columns: ['PID', 'Name', 'CPU %', 'Memory', 'Status'],
    rows: []
  },
  container: '#processes',
  theme: { striped: true, hoverHighlight: true }
});

source.on('data', (point) => {
  if (point.processes) {
    processTable.update({
      data: { rows: point.processes }
    });
  }
});

6 Error handling

Every widget should handle errors gracefully. Subscribe to the error event:

cpuChart.on('error', ({ error, phase }) => {
  if (phase === 'render') {
    console.warn('Chart render failed, falling back to table view');
    cpuChart.update({ type: 'table' }); // graceful degradation
  } else if (phase === 'data') {
    console.error('Invalid data received:', error);
  }
});
Warning: Always handle the error event. Unhandled widget errors propagate to the global error handler and can crash your app.

Connection loss handling

The MetricsSource reconnects automatically, but the widgets need to know the connection state:

source.on('disconnect', () => {
  statusCard.update({ data: { status: 'reconnecting' } });
  cpuChart.update({ theme: { opacity: 0.5 } }); // dim the chart
});

source.on('data', () => {
  statusCard.update({ data: { status: 'live' } });
  cpuChart.update({ theme: { opacity: 1.0 } }); // restore
});

7 Testing

Widgets are testable in JSDOM or with a headless browser. Here's a basic unit test:

// test/widgets.test.js
import { describe, it, expect, beforeEach } from 'vitest';
import { createWidget, destroyWidget } from 'widgets';

describe('CPU Chart', () => {
  beforeEach(() => {
    document.body.innerHTML = '<div id="chart"></div>';
  });

  it('creates and mounts', () => {
    const chart = createWidget('test-chart', {
      type: 'line',
      data: { labels: [], datasets: [] },
      container: '#chart'
    });
    expect(chart.getState().mounted).toBe(true);
  });

  it('updates data correctly', () => {
    const chart = createWidget('test-chart', {
      type: 'line',
      data: { labels: [], datasets: [{ values: [] }] },
      container: '#chart'
    });

    chart.update({
      data: { labels: ['a', 'b'], datasets: [{ values: [1, 2] }] }
    });

    expect(chart.getState().data.labels).toEqual(['a', 'b']);
  });

  it('cleans up on destroy', () => {
    createWidget('test-chart', {
      type: 'line',
      data: {},
      container: '#chart'
    });
    destroyWidget('test-chart');
    expect(() => destroyWidget('test-chart')).not.toThrow();
  });
});

Run with: npx vitest run

8 Deployment

For production, use a bundler and serve the static files. Here's a minimal Vite config:

// vite.config.js
import { defineConfig } from 'vite';

export default defineConfig({
  build: {
    outDir: 'dist',
    minify: 'terser',
    sourcemap: true
  },
  server: {
    proxy: {
      '/ws': {
        target: 'ws://localhost:8080',
        ws: true
      }
    }
  }
});

Deploy to any static host (Vercel, Netlify, S3 + CloudFront):

npm run build
npx serve dist
Congratulations! You've built a real-time dashboard with widgets.js. The final app has a line chart, a status card, a process table, error handling, and automatic reconnection.
