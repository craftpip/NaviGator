Getting Started

What is CloudStack and how does it work?

CloudStack is a modern deployment platform that lets you ship web applications in seconds. Connect your Git repository, and we handle building, deploying, and scaling your app across 38 regions worldwide.

Key features:

  • Zero-config deploys — push to main, we deploy automatically
  • Preview deployments — every pull request gets its own URL
  • Edge functions — run server-side logic at the CDN edge
  • Real-time logs — debug production issues without SSH
How do I deploy my first project?

Three steps:

  1. Click "New Project" in your dashboard
  2. Connect your GitHub/GitLab repository
  3. Select a framework preset (or use our auto-detection)

That's it. CloudStack detects your framework, installs dependencies, builds, and deploys. Average deploy time: 28 seconds.

# Or deploy from CLI
npm install -g cloudstack-cli
cloudstack deploy --project my-app
Which frameworks are supported?

We have first-class support for:

  • React — Next.js, Remix, Gatsby, Vite
  • Vue — Nuxt, Vite, Quasar
  • Svelte — SvelteKit
  • Astro — full SSR + SSG
  • Static — any HTML/CSS/JS site
  • Backend — Node.js, Python, Go, Ruby

We also support custom build commands via cloudstack.json for any framework.

Can I use my own domain name?

Yes. Add your domain in Project Settings → Domains. We'll provision an SSL certificate automatically (Let's Encrypt) and give you DNS records to point to CloudStack.

For advanced setups, you can use:

  • CNAME pointing (recommended)
  • A record pointing (requires IP allocation)
  • Wildcard domains for multi-tenant apps

Deployment & Configuration

How do environment variables work?

Set environment variables in Project Settings → Environment. They're available during build and runtime.

We support three scopes:

  • Production — available on the production URL
  • Preview — available on preview deployments
  • Development — available in local dev via cloudstack env pull

Secrets are encrypted at rest and never exposed in logs or client-side code.

What happens if my build fails?

You'll get an email and a dashboard notification with the full build log. Common causes:

  • Missing package.json or build script
  • Node.js version mismatch (we default to LTS; override with "engines": {"node": "20.x"})
  • Out-of-memory during build (upgrade to Pro for 4GB build RAM)
  • Dependency install failure (check your lock file)

The previous successful deployment stays live until you push a new one.

How do I set up a custom build pipeline?

Create a cloudstack.json in your repo root:

{
  "buildCommand": "npm run build",
  "outputDirectory": "dist",
  "installCommand": "npm ci",
  "framework": null,
  "regions": ["us-east", "eu-west"]
}

You can also use prebuild and postbuild hooks for database migrations, asset generation, etc.

Can I deploy Docker containers?

Yes. Add a Dockerfile to your repo and set "framework": "docker" in cloudstack.json. We'll build your image and deploy it on our managed infrastructure.

Multi-stage builds are supported and recommended for smaller images. We cache build layers automatically.

Troubleshooting

A 502 means your server-side code is crashing or not responding. Check:

  • Function logs — go to your project → Logs → filter by "function"
  • Memory usage — free tier has 256MB; upgrade if you're hitting limits
  • Timeout — serverless functions have a 10s timeout (30s on Pro)
  • Crash loop — check for unhandled promise rejections or missing env vars

Common optimizations:

  • Use npm ci instead of npm install (frozen lockfile)
  • Enable build caching in Project Settings → Build
  • Exclude dev dependencies: set NODE_ENV=production
  • Use our Incremental Builds feature (Pro) — only rebuilds changed pages

For preview deployments, use the browser console directly. For production:

  • Source maps — upload them in Project Settings → Debugging
  • Error tracking — we integrate with Sentry, Datadog, and LogRocket
  • Analytics — our Web Vitals dashboard shows real-user performance data
