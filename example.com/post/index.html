Why Test Pages Matter

By Test Author · Published 2026-08-01 · 8 min read

When you build a web extraction tool, the very first thing you need is a page you control completely. No ads, no paywalls, no JS frameworks, no bot protection. Just clean semantic HTML.

This article contains every HTML building block an extractor should handle: headings, paragraphs, lists, tables, blockquotes, code, definitions, abbreviations, footnotes, and complex inline formatting.

The building blocks

Every serious article on the web uses a combination of these elements. An extractor that handles all of them cleanly is an extractor that handles most of the real web.

Headings

The hierarchy matters. A good extractor preserves the outline:

  1. <h1> — the page title (one per page)
  2. <h2> — major sections
  3. <h3> through <h6> — subsections

Inline elements

Text can contain bold, italic, links, inline code, abbreviations, highlighted text, deleted text, inserted text, subscript, and superscript. A good extractor preserves the meaning of these elements, not just the text.

Definition lists

Definition lists (<dl>) are used for glossaries, metadata, and key-value pairs. Many extractors ignore them entirely.

Extractor
A tool that pulls structured content from web pages, removing navigation, ads, and other non-content elements.
Readability
An open-source content extraction algorithm (mozilla/readability) that scores DOM nodes based on text density and structural signals.
DOM
The Document Object Model — a tree representation of an HTML document that browsers and extractors parse into nodes.
Selector
A CSS pattern used to identify specific elements in the DOM. Example: article > h2 selects all <h2> elements that are direct children of <article>.
Content score
A heuristic value assigned to each DOM node by extraction algorithms. Higher scores indicate more likely content. Calculated from text length, paragraph count, and class/ID patterns.
Signal-to-noise ratio
The proportion of meaningful content vs. structural noise (nav, footer, ads) on a page. Higher is better for extraction. A typical news page has a ratio of about 0.3 to 0.6.

The five principles of good extraction:

  • Preserve document structure (headings, lists, sections)
  • Remove non-content elements (nav, footer, ads)
  • Maintain inline formatting (bold, italic, links)
  • Handle tables as structured data
  • Respect the author's intended reading order

Code blocks

Technical articles are full of code. Here's a JavaScript example:

// A simple content extractor
function extractContent(doc) {
  const article = doc.querySelector('article') || doc.querySelector('main');
  if (!article) return null;

  const headings = [...article.querySelectorAll('h1, h2, h3')];
  const paragraphs = [...article.querySelectorAll('p')];

  return {
    title: headings[0]?.textContent || '',
    sections: headings.map(h => ({
      heading: h.textContent,
      content: getNextSiblings(h, 'p')
    })),
    wordCount: paragraphs.reduce((sum, p) =>
      sum + p.textContent.split(/\s+/).length, 0)
  };
}

And here's a Python example with a different syntax style:

import requests
from bs4 import BeautifulSoup

def fetch_and_extract(url: str) -> dict:
    """Fetch a URL and extract readable content."""
    response = requests.get(url, timeout=30)
    soup = BeautifulSoup(response.text, 'html.parser')

    # Remove non-content elements
    for tag in soup.select('nav, footer, aside, .ad, .sidebar'):
        tag.decompose()

    article = soup.find('article') or soup.find('main')
    return {
        'title': article.find('h1').text if article else None,
        'text': article.get_text(separator='\n', strip=True),
    }

Inline code like document.querySelector() and BeautifulSoup should be distinguished from regular text.

Mathematical expressions

Some articles contain inline math. Here's the formula for content score:

S(node) = wtext · L(node) + wpara · P(node) + wstruct · C(node)

Where:

L(node)
The text length of the node (in characters)
P(node)
The number of paragraph-like child elements
C(node)
A structural complexity score based on nesting depth
wtext, wpara, wstruct
Weighting factors (typically 0.5, 0.3, 0.2)

Footnotes

Footnotes are common in academic and long-form writing.[1] They create a cross-reference between the text and the notes section.[2]

Some extractors strip footnotes entirely. Others keep them inline. The best approach is to preserve them as numbered references and keep the notes section at the bottom.
